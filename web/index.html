Observations

Written automatically from your measured results.

1. An image is three matrices

An n × n colour image is stored as three n × n matrices: one each for Red, Green and Blue, with values from 0 to 255. Call them P.

2. Encryption is a matrix multiplication

C = K × P  (mod 256)
C[i][j] = ( Σk=0..n−1 K[i][k] · P[k][j] ) mod 256

K is a random n × n key matrix. Every encrypted pixel depends on a whole column of the original image, so the result looks like random noise. Decryption multiplies by the inverse key:

P = K⁻¹ × C  (mod 256)

3. Making a key that can be inverted

A matrix has an inverse mod 256 only if its determinant is odd. We build K = L × U, where L is lower-triangular with 1s on the diagonal and U is upper-triangular with random odd numbers on the diagonal. Then det(K) = det(L) · det(U) = 1 · (product of odd numbers), which is always odd.

Triangular matrices are easy to invert by substitution, and K⁻¹ = U⁻¹ × L⁻¹. The seed you type decides the random numbers, so the seed works like a password.

5. Complexity

Every method does the same total work: n³ multiply-adds per channel, so O(n³). Threads don't reduce the work; they share it across cores. With p cores the best possible time is about T(n) ≈ n³ / p + overhead.

  • Thread creation cost: starting a thread takes tens of microseconds. Thread per cell starts n² threads but gives each one only n multiplications, so the overhead is far bigger than the useful work.
  • More threads than cores don't run at the same time. The operating system has to switch between them, which adds more overhead.
  • Thread per row only pays off when each row has enough work (large n) and there are several cores.
  • A thread pool creates only p threads and reuses them, which is how real software (and Java's parallel streams) does it.

6. Limitation (good to mention in the viva)

This is a Hill-cipher-style cipher and it is linear: if an attacker knows one original image and its encrypted version, they can solve for K. Also, two identical columns in P give identical columns in C. Real systems use AES. This project is about the algorithm and its performance, not production security.

Viva questions

Why is thread per cell the slowest?

It creates n² threads (262,144 for 512 × 512). Creating and scheduling a thread costs far more time than the n multiplications each thread does.

What is the time complexity?

O(n³) for every method. Parallelism divides the running time by at most the number of cores; it doesn't change the total work.

Why transpose P before multiplying?

So column j of P becomes a contiguous array in memory. The dot product then reads memory in order, which uses the CPU cache well. All methods use it, so the comparison stays fair.

Why mod 256?

Pixel values must stay between 0 and 255. Working mod 256 keeps every result a valid pixel and lets the inverse key recover the image exactly.

Why must the determinant be odd?

A matrix is invertible mod m only if its determinant has an inverse mod m. Mod 256 = 2⁸, only odd numbers have inverses.

Why can speed-up not exceed the core count?

Only p threads can run at the same instant on p cores. With 2 cores the best case is 2× faster; overhead usually makes it a bit less.

Why is the first run slower?

Java's JIT compiler optimises code after it has run a few times. The benchmark warms up first and reports the median of several runs.

Could we use Strassen's algorithm?

Yes: Strassen is O(n2.81) and is a good extension. It's worthwhile only for large matrices because of its extra additions.
